# Materials Project单一数据源映射与一致性策略

## 1. 单一主设计源

正式候选池、模型训练、策略评价和D2以上研究信号只允许使用Materials Project数据。C2DB、论文和实验数据以后可以用于背景论证或外部验证，但不得混入主训练集和统一基线评价。160条随机合成记录永久限定为软件测试夹具，不能进入科学候选池。

逐字段一一映射见`config/materials_project_mapping_list.json`。每项记录原名称、映射后名称、类型、单位、是否必需与使用说明。探索状态字段统一使用`exploration_status_`前缀，以便与MP原始字段、性质字段和审计派生字段区分。

## 2. 一致性与简单函数底层思路

本项目继续使用已经确定的简单、透明、可复现函数作为MVP底层评价规则：

\[
S=\mathbf 1(E_f\le-0.2)\land
\mathbf 1(E_{hull}\le0.1\lor is\_stable),
\]

\[
H=\mathbf 1(1.5\le E_g\le2.5).
\]

D2的最低数值条件为`S=1`且`H=1`，并同时要求MP身份可追溯和二维性确认。三种策略继续在相同候选池、相同初始样本、相同20次查询预算下比较D2数量、命中率、首次D2所需预算和MAE；评价标准不因映射变化而改变。

这里必须区分两类“简单函数”：

1. 对真实MP数据，函数只负责筛选和评价，输入直接使用MP记录值，不重新生成或篡改性质；
2. 对160条测试数据，简单函数用于生成人工Formation Energy、Energy Above Hull和Band Gap，只验证闭环代码，没有科学依据。

## 3. 新增优化约束及理由

| 新增约束 | 设计 | 理由 |
|---|---|---|
| 数据库版本冻结 | 一次正式实验只用一个MP版本 | 防止数据库更新改变候选池与反馈值 |
| 计算方法队列冻结 | 主训练与评价队列只用一种明确方法 | 防止不同计算口径的系统偏差被策略误当成结构规律 |
| 缺失方法隔离 | 方法字段缺失进入人工审核队列 | 不用猜测补齐关键来源信息 |
| MP ID唯一 | MP ID为候选主键，formula仅分组 | 同化学式可能对应多个结构多型 |
| 原始值不可覆盖 | 原始响应与规范化字段分层保存 | 支持审计、重新映射和数据库版本比较 |
| 二维性确认门槛 | 仅`confirmed_2d`进入科学池 | MP是通用材料库，公式检索不等于二维确认 |
| 方法不一致不做经验换算 | 第一版不拟合跨方法校正曲线 | 样本和误差依据不足时，简单线性换算会制造伪一致性 |

这些约束可以减少样本量，但提高初赛要求的可检查性、可复现性与失败可解释性。

## 4. 与初赛PDF的关系

- §2.1：MP单一数据源、版本/方法冻结、映射表和简单评价函数属于不可改变规则；
- §2.2：观察使用规范化字段，行动以MP ID选择候选，反馈返回MP性质值；
- §2.3：日志记录MP版本、计算方法、映射版本、预算及`exploration_status_*`状态；
- §3.1：D2使用同一简单函数评价，但增加来源、方法和二维性审计；
- §3.2：三种策略使用完全相同的数据版本、计算方法和评价函数；
- §3.3：数据源、版本或方法不一致即判定该轮科学评价无效，但保留失败证据；
- §4.1：试跑输入首先经过映射与一致性门控；
- §4.2：字段缺失、方法混合和数据库漂移进入审核/失败路径；
- §4.3：映射list、规则版本和MP查询条件随仓库开源。
